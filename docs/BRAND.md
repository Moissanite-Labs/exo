# Exo brand

Status: proposed (D-049). The brand page is `site/brand/index.html`; every asset there is generated by
`scripts/brand_assets.py` (`--png` also renders the PNG icons with headless Chrome). Until D-049 is accepted, the live
site keeps its current nav mark, favicon and orb.

## The figure

Everything comes from one drawing. Draw a square of side 2 and both diagonals: the diagonals are an X and cut the
square into four right isosceles triangles. In each triangle, mark the incentre, the one point equally far from all
three sides. It sits R = √2 − 1 = tan 22.5° ≈ 0.414 above the side. Join each dot to its triangle's three corners.

- Tiled, the dots of four neighbouring squares form a regular octagon: the 4.8.8 tiling.
- Lifted to a cube of side 2, the six incentres sit on the axes at K = 2 − √2 from the centre. Stacked cubes give the
  truncated cubic honeycomb; every edge has length 2R.
- In n dimensions the numbers do not change: 2n dots per cell, each touching 2n − 1 others.

Credit: the geometry, and every number above, follows the open research project Incentre lattice
(aska-digital/incentre-lattice, https://aska-digital.github.io/incentre-lattice/). The classical results it rests on
(the incentre, the Wythoff construction as developed by Coxeter, the uniform tilings and honeycombs) belong to
everyone. Exo takes the geometry only; that project's colours and type are its own and are not used here.

## The X/V rule

1. The x in "exo" is the square's X: two strokes at exactly 45°, with flat horizontal terminals.
2. Its top half, the two upper arms, is `#ff5b14` and reads as a V, so the word also reads as "evo". The V owns the
   crossing: the lower legs stop at the V's lower edges.
3. Nothing else in the wordmark is orange. In the mark only the V and the top dot (the seed) are orange.
4. The e and the o are cut from regular octagons. A regular octagon of height h has side h(√2 − 1), the same number.
5. Never outline, stretch, rotate or recolour the V. In one colour, the V is solid and the legs are a 40% tint.

Geometry (units, x-height 20): stroke 4, letter gap 3.2, the x is 20 + 2·(4/√2) wide. At 16 px tall the stroke is
3.2 px. The e's aperture is cut along a 45° line, square to the stroke.

## The egg

`site/brand/egg.js` draws the lattice as a living orb. No dependencies, Canvas 2D, one file. Under
`prefers-reduced-motion` it draws one still frame (a lit path through a few cells) and never animates. It pauses when
off screen or in a background tab. Measured cost: under 0.5 ms of script per frame at stage 4 (510 dots, 2,130 edges).

What moves: packets of information travel along the edges, one hop at a time; a dot they reach lights orange and its
cell glows, with its lines to the cell centre (the drawing's line to the centre). A heartbeat in the core cell sends
packets out. Activity sets the beat rate and the background traffic.

### Stages

| Stage | Name | Dimension | Cells | Dots | Shell | Brightness |
|---|---|---|---|---|---|---|
| 0 | egg | 3 | 1 (the yolk: an octahedron) | 6 | closed | 0.62 |
| 1 | hatchling | 3 | 7 (plus the face cells) | 42 | cracking, fading | 0.74 |
| 2 | lattice | 3 | 19 (plus the edge cells); the first cube drawn | 114 | gone | 0.86 |
| 3 | hyper | 4 | 33; the fourth axis unfolds out of the third | 264 | gone | 1 |
| 4 | spare | 5 | 51 | 510 | gone | 1 |

Stages are a float from 0 to 4. Each element appears over one unit of stage, so 1.5 is halfway between hatchling and
lattice. Dimension is continuous too: from stage 2 to 3 the fourth coordinate is scaled from 0 to 1, so the 4D cells
grow out of the 3D ones. The shell is the same honeycomb, one ring further out, pushed onto an egg shape; its edges drop
out as it hatches. Cells are the lattice cells with |c|² ≤ 2 in integer cell coordinates.

### API

```js
// <script src="/brand/egg.js"></script>  defines window.ExoEgg
var egg = ExoEgg.mount(canvas, {
  stage: 0,            // 0..4, float
  activity: 0.5,       // 0..1
  seed: 7,             // random seed, for repeatable traffic
  shell: true,         // false hides the egg shell
  spin: 1,             // rotation speed multiplier
  reducedMotion: undefined,  // true/false overrides the media query
  layout: function (W, H) { return { cx: W / 2, cy: H / 2, r: Math.min(W, H) * 0.4 }; }
});
egg.setStage(2);                    // eases there at 0.7 stages per second
egg.setStage(2, { immediate: true });
egg.getStage();                     // the current, possibly in-between, stage
egg.setActivity(0.8);
egg.pulse(6);                       // send 6 packets out of the core (a turn starts, a tool runs)
egg.pause(); egg.resume(); egg.destroy();
ExoEgg.STAGES;                      // the table above, as data
ExoEgg.MAX_STAGE;                   // 4
```

Repository events (proposed, D-059): `egg.event(type, {replay, weight})` for `issue`, `pr`, `review`, `merge`, `release`
and `validated` (with a `kind`), `egg.meditate(on, {immediate})`, `egg.meditating()`, `egg.signal(level)` and
`egg.queued()`. The contract is `docs/LIVE-EGG.md` section 1.2. `pulse(n)` keeps its meaning.

Without script: `<canvas data-exo-egg data-stage="2" data-activity="0.6" data-seed="3" data-shell="off">` is mounted
on load (`ExoEgg.autoMount(scope)` mounts canvases added later). The canvas fills its CSS box.

For exopet: map the evolution line onto stages 0 to 3 (4 is spare) and drive `activity` and `pulse` from real events.
Keep the stage meaning (more cells, more structure, a dimension, more light) so the pet and the brand stay one figure.

## Gallery image loading (#258)

The below-fold images inside the brand page's main gallery use browser lazy loading and asynchronous decoding. Width and height hints reserve their boxes before image bytes arrive; missing hints come from the SVG viewport, rounded to whole CSS pixels. Existing deliberate display sizes and the eager navigation logo remain unchanged.

Local browser tests block gallery image requests, measure the reserved boxes, then decode every image and compare geometry at desktop and narrow widths. This is source-level gallery work, not a transfer-byte, Lighthouse, staging or production claim. WebP/AVIF variants, srcset, deduplication, deployment copying, cache headers, unused assets, robots/sitemap/manifest and the rest of #258 remain open.
